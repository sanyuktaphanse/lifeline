# Wise sandbox run of 16 October 2026

This is the operation log of one run of `make evidence-wise` against Wise's sandbox, generated on 16 October 2026 on the team's own machine and copied here unchanged below the next heading. The run asks Lifeline, through its own API, to send 25 SGD from the demo student to their own Singapore account twice. Each time the mandate engine checks the proposal, the student confirms with the engine's token, and the Wise sandbox rail quotes, creates and tries to fund the transfer.

The account is a personal Wise sandbox account, with a personal API token, one profile and one SGD recipient for the payee self_sg. The SGD balance was funded, and the balance row in the log shows 1000.0 SGD held when the first payment was refused, so the refusal was not for lack of money.

Both quotes worked, the engine allowed both transfers under R11, and Wise created both transfers. Wise then refused to fund each one with a 403 answer that carried its strong customer authentication headers. That refusal is Wise's policy for personal accounts. Wise's sandbox shows this notice on its public keys page:

> As part of our ongoing improvements in compliance with requirements specified in the Payment Services Directives (PSD2), we no longer support signing API requests to complete strong customer authentication on personal Wise accounts. You can no longer retrieve account statements or fund payments using this method. It is still possible to create draft transfers using our API and fund them from your multi-currency account using our website or mobile applications.

So with a personal account the rail can quote and create a transfer on Wise but cannot fund it. Only a business account can, and the team does not have one. After each refusal the rail asked Wise to cancel the draft transfer; the log does not record whether Wise accepted that cancel. Because no transfer was funded, no receipt was issued, and the trace, simulate and cancel steps the run takes after a receipt do not appear.

The quote ids and the transfer ids in the table, 2149538157 and 2149538162, are real objects in Wise's sandbox. No money moved: the sandbox holds no real money, and neither transfer was funded.
